UI simplification — three directions

Same data, same three live controls (add source, disconnect, update). They differ in how much structure survives around them.

The dead controls. Seven of the eight buttons in the current table do nothing: select-all, per-row checkboxes, both column sorts, preview, download, more, download-selected, expand, and the pager. The top bar is dead outright. A removes only the top bar and leaves the rest exactly as it is; B and C also drop the inert controls, which is a separate decision from the one A makes. Sample vendors are used throughout so the vendor column can actually be judged.

A

Stripped

same skeleton, dead weight removed open ↗

The current UI with the top bar deleted, and nothing else changed. Rendered from the app’s own dashboard.css, so this is the real thing rather than a redrawing of it.

  • No top bar: “Settings” had no page, “Dashboard” was the only destination, the user menu had no menu
  • Table keeps every column, control and the pager
  • Smallest possible diff — one component deleted
  • The inert controls stay inert; removing them is a separate decision
B

Unified

one card, sources as chips open ↗

Collapses the sidebar into the table’s own toolbar, so the page holds one object instead of two.

  • Sources become chips, × on hover to disconnect
  • Table gets the full width; page narrows to feel deliberate
  • Update is the one filled button — the only routine action
  • Chips get cramped past ~4 accounts
C

List

Stops treating this as a data grid. No cards, no borders, no header row — the invoices are the page.

  • Grouped by month, with a monthly total
  • Date column dissolves into the group heading plus a day line
  • Sources shrink to one quiet line under the title
  • Furthest from today’s markup — largest rewrite
  • Scales worst to hundreds of rows without paging
