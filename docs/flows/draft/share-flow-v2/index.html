Share flow, redesigned

Handing a batch of invoices to someone who has no account — an accountant, a co-founder, a client. Same flow as share-flow, same data model, same routes; what changed is everything the redesign skill audit turned up. Each frame is a real page linked against the app’s own tokens.css and dashboard.css, so these cannot drift from the product.

Two clicks to a live link

Update, then the share icon — the link is minted and on the clipboard before any dialog asks anything. Five things deliberately do not exist, because each one is a decision the user would otherwise make before getting their link:
  1. No share dialog. The click is the share. The popover reports, it does not ask.
  2. No expiry, password, or permission levels. Live until revoked; revoke is the one switch.
  3. No separate preview. “Open the link” opens the exact URL the recipient gets.
  4. No picking. The link is the batch — no checkboxes, no partial zip. Wrong batch? Tick rows on the dashboard and share again; it is still two clicks.
  5. No attachments. The mail carries the summary and a button. 12 MB does not.

What the redesign changed

The full diagnosis is in audit.md. In one list:
  • Geist and a mono in place of the Inter/system stack, with every figure set tabular.
  • One accent. The signal red drops to oxide; the green that carried “success” is gone.
  • One overlap. The document card lifts into the header band, so the page has a foreground.
  • The five thumbnails fan like paper instead of sitting in a row of equal boxes.
  • Press, focus and hover on every control; grain and tinted shadows on every surface.
  • Four states v1 never drew — loading, downloading, a bad address, and a 404.

Link created

The link already exists and is already on the clipboard — nothing to confirm. The response also carries an owner_key, which this browser keeps in localStorage and never shows anyone; it is what gates sending and revoking later. The snapshot of invoice ids is frozen here, so a later scan cannot silently widen a link that has already gone out.

The two actions are no longer a filled button beside an outlined one. A matched pair reads as two equal decisions, and only one of them is the point — so opening the link is the button and sending it by email is a text link.

While the manifest loads

A manifest of 37 rows is a request, and a request has a duration. v1 drew no loading state at all, which in practice means a blank page for its length.

The skeleton is shaped like the page it stands in for — band, fan, rows — so nothing jumps when the data lands, and the shimmer is a transform, not an animated left. A centred spinner would say only that something is happening.

4

The share page

GET /s/{token} Anyone with the link open full screen ↗

The filename is the biggest thing on the page, because “is this the right export?” is the only question the page has to settle before anyone clicks. Under it, four labelled facts — invoices, documents, size, period — instead of v1’s single 15px line with separators.

Below that the page is laid out as the zip’s contents: a pdf part and a csv part, each named and chipped with its file type, under a header already chipped zip. No sentence says “you are downloading PDFs and a spreadsheet” — the layout says it. The five thumbnails are rendered server-side at extraction time and fan like a stack of paper; five is the whole strip, so there is no lazy loading and nothing to virtualize.

The table is a sheet, not a working surface — hairline grid, 32px rows, tabular mono, the zip’s own filenames, counts on the last line, and a sticky header so the column names survive row 30. Row 6 shows dashes where Bolt’s ride receipt carries no invoice number and no VAT split: that is the real shape of the data.

The ninth column is not data — it counts what the CSV has and the page does not (+15 in csv). Narrow screens drop columns into that count, so the number stays true at every width. The document card lifts into the header band; that one overlap is what stops the page reading as six stacked stripes.

Preparing the download

The zip is streamed and never assembled on disk, so its size is known before the first byte — which means this can be a determinate bar rather than a spinner. v1’s download button was an href="#" with no state after the click.

The panel replaces the button in place, so nothing moves, and it names what is being built: 36 documents and the CSV.

Optional — sending it for them

6

Composer

Owner open full screen ↗

One field the user must fill: the address. Subject and body are already drafted, and the mail goes out from a connected mailbox — Unipile already holds those credentials, so there is no second OAuth and no Gmail client to write.

From states the answer rather than asking a question — the address as text, the way it would read on a sent message, with a caret beside it if there is anywhere else to send from. It is a span, not a select, and its label is a span too: a <label for> pointing at no control promises a screen reader something that is not there.

The draft is right there underneath, in an iframe over the real rendered mail — the same document the API sends, not a mock-up of it. The composer is now its own raised card sitting in front of the document, because writing a mail is a different task from reading a manifest.

Choosing the mailbox

GET /accounts Owner open full screen ↗

The caret exists only because two mailboxes are connected; with one it is not rendered, because a control that leads nowhere is worse than no control. With two — personal and billing, say — which one sends is a real question, and it decides where the reply lands.

The current mailbox stays in the list and is ticked, so the menu answers which am I on? as well as what else is there? The choice is remembered, so it is asked once rather than every time.

The address needs fixing

The one field in this flow was the one field with no validation. Checked on blur, before anything is sent: aria-invalid, aria-describedby, a tinted border, and a sentence that says what is wrong and guesses the fix rather than “invalid input”.

Send is disabled while it is — aria-disabled, not a dead button that fails silently on click.

Confirmation names who it went to and which mailbox it came from, because “sent” alone leaves the user checking their own Sent folder. Sending again to someone else is one click and reuses the same link.

The email

Recipient open full screen ↗

Shaped like a receipt: a branded band, one heading, a short label/value block, one action. No thumbnails, no vendor list, no marketing — the page has all of that, and an inbox is not where anyone reviews 37 invoices. Dropping the images also drops the third of clients that block them.

600px, tables, inlined styles, plain-text alternative — the format that survives Outlook. No attachment: 12 MB bounces, lands in spam and goes stale; a link does none of that. One line of v1’s copy was cut here because it was false: it promised that any invoice “can be opened before you download”, and nothing on the page opens a single document.

Recipient’s view

The same page as screen 4, minus the owner strip — no login wall, no “request access”, nothing to install. Because owner and recipient share one page, there is no what-they-will-see mode to keep in step, and no doubt in the owner’s mind about whether the preview was accurate.

Revoked

DELETE /s/{token} Anyone with the link open full screen ↗

Says so plainly rather than 404ing. The recipient knows the link once worked, so pretending it never existed reads as a bug — and naming who turned it off tells them who to ask. A dead end needs a way out, so it has two: mail the sender, or go back.

A 22-character token in an email is a token that gets broken across two lines, so the likeliest 404 in this product has a known cause — and the page names it instead of saying “page not found”.
