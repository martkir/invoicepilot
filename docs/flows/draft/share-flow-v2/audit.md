# Redesign audit — share flow

Run of [`.claude/skills/redesign-existing-projects`](../../../.claude/skills/redesign-existing-projects/SKILL.md)
against [`docs/flows/share-flow`](../share-flow/index.html). The skill's sequence is
**scan → diagnose → fix**; this file is the diagnosis and the fix log. The
result is [`index.html`](index.html) beside it — the same flow, the same data
model, the same routes.

---

## 1. Scan

| | |
| --- | --- |
| Framework | None in the mockups. React 19 + Vite in the app the mockups link into. |
| Styling | Vanilla CSS, custom properties, no preprocessor, no utility framework. |
| Dependencies | `services/web/package.json`: React, React DOM, Vite, TypeScript. **No icon library, no font package, no CSS framework.** |
| Structure | `tokens.css` (palette) → `dashboard.css` (shipped chrome) → `flow.css` (the proposed share UI). Screens generated by `build.py`. |

Two consequences shaped everything below.

**The mockups link the app's real stylesheets.** So a change to the palette
cannot be a mockup-only flourish — it lands on the product or it does not
happen. This folder is arranged so that is literally true:
[`tokens-v2.css`](tokens-v2.css) redefines the same custom properties
`tokens.css` declares, and [`redesign.css`](redesign.css) is a diff against
`dashboard.css`. Shipping the redesign means pasting the first over
`services/web/src/styles/tokens.css` and folding the second into
`services/web/src/styles/dashboard.css`. Nothing was forked.

**No library gets added.** The skill's rule — check the dependency file before
importing anything — rules out swapping Lucide for Phosphor, since Lucide was
never a dependency in the first place: the icons are inline SVG paths copied
into `build.py`. So the icon fix is a redraw, not an install.

**On removing the green.** The skill says pick one accent and remove the rest,
and that collides with the convention that success is green. The call here: the
tick mark and the sentence carry "sent", and the accent carries the mark — so
the palette stays at one hue. The cost is that the send-failure notice and the
success banner are the same colour family, distinguished by structure (a left
rule, a heading, a `code` block with the transport error) rather than by hue.
That is a real trade and it is the one place in this audit where a reviewer
might reasonably rule the other way.

## 3. Fix log

The skill's order — highest impact, lowest risk first. Everything landed in
this order and each step was rendered before the next started.

1. **Font swap.** Geist and Geist Mono, with the old stack as fallback so an
   offline open degrades to what v1 looked like rather than to nothing.
2. **Palette cleanup.** One accent, desaturated; one grey family, warmed;
   shadows tinted and layered; the green removed.
3. **Hover, press and focus.** Every control, plus the focus halo.
4. **Layout and spacing.** The header band, the one overlap, the asymmetric
   documents part, the sheet's sticky head, optical padding.
5. **Component replacements.** The button set gains a tertiary rung; the
   thumbnail row becomes a fan; the vendor circles become rounded squares.
6. **The missing states.** Loading, downloading, invalid address, 404.
7. **Typographic polish.** The display line, tabular figures everywhere,
   sentence-case labels, `text-wrap`, the measure caps.

Functionality was not touched: same routes, same data model, same five things
that deliberately do not exist. `build.py` still generates every screen from
one set of fragments, so the redesign cannot drift between them.

## 4. Declined, and why

The skill is a checklist, not an instruction set. Six items were considered
and not applied.

- **Background imagery from `picsum.photos`.** The suggestion targets marketing
  pages with empty hero sections. This is a document someone opens to check
  whether a zip is the right zip; a stock photograph behind it would be noise
  with a licence attached. The flat-section problem it exists to solve is real
  here, and it is solved with grain, an ambient radial and one overlap instead.
- **Serif/sans pairing.** Applied to [`index.html`](index.html) — the contact
  sheet is a document about a product, and Fraunces suits it — and deliberately
  not to the product screens, which stay one family. A share page is not
  editorial.
- **"Dashboard always has a left sidebar → try top navigation."** The
  dashboard's left column is a sources card, not navigation, and the flow being
  redesigned is the share flow. Moving the app's primary layout would be a
  different change with a different blast radius.
- **Cookie consent.** The share page sets no cookies and runs no analytics. The
  `owner_key` in `localStorage` is functional storage for the browser that
  created the link. A consent banner would be a banner about nothing.
- **An empty state.** There is no empty share: `POST /shares` with an empty
  snapshot is a request that should not be made, and the button that makes it
  is disabled when the table has no rows. The nearest real thing — a share
  whose invoices have all been deleted — is a data-integrity bug, not a screen.
- **Variable-font animation, scroll-driven reveals, parallax stacks, smooth
  inertial scroll.** All four are in the skill's upgrade list. All four are for
  pages that are performed. This one is read once, quickly, often by someone
  who is annoyed about a quarter-end deadline. The motion here is the pressed
  buttons, the popover arriving from its control, and the skeleton — nothing
  that delays a fact by a frame.

## 5. What did not change

The information design, in full. The redesign did not touch:

- The five things that deliberately do not exist — no share dialog, no expiry
  picker, no separate preview, no picking on the share page, no attachments.
- The `shares` table, the `owner_key` split, the frozen invoice-id snapshot.
- Every route, verb and payload.
- The page laid out as the zip's contents: a `pdf` part and a `csv` part under
  a header chipped `zip`.
- Eight columns on the sheet plus the ninth that is not data but a count of
  what `invoices.csv` carries and the page does not — including the way that
  count tracks the breakpoint.
- Five thumbnails and no scrolling; no single-document route; no summed amount
  anywhere.
- The mail's shape: a receipt, one action, no images, plain-text alternative.

That is the point of the exercise. Everything in §2 is a finish problem, and
none of it required an argument about what the flow is for — which is also why
the whole audit fits in one folder of CSS and one generator.
