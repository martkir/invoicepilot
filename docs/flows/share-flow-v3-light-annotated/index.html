What the map asked, and what was decided

Found while mapping the screens to routes, and settled afterwards. Each one is pinned on the screen that raised it; revisions.md names the commit each answer landed in.

  1. Your link / martin@kirov.dev 03-preview.html

    `shares` as first specified carried no owner at all, so neither this line nor its recipient-facing twin could be filled. Settled 2026-08-15: two columns, `owner_name` and `owner_email`, written at creation from the connected mailbox and frozen with the snapshot. Deriving them at read time from the invoices was the alternative and is worse - the mailbox that received an invoice is not necessarily the person sharing it, and disconnecting an account would rewrite what a link already sent says about who sent it.

  2. It stops working on 12 July 2026 03-preview.html

    This line used to be a Revoke button. Settled 2026-08-14 in notes.md and drawn 2026-08-15: no DELETE /s/{token}, no `revoked_at`, and a fixed seven days set at creation instead. What replaced the control is not another control but the fact it would have been used to establish.

  3. The preview 04-compose.html

    No route in any spec served this, and the design rules out the alternative by name: the iframe must show what is about to be sent, not a look-alike. Settled 2026-08-15 - the route exists, GET /api/s/{token}/email/preview, and it is the tenth endpoint in the map. A second template that could drift from the sending one was the only other answer.

  4. Shared with you by Martin Kirov 07-recipient.html

    The same question as 03-preview.html and the reason it had to be answered rather than dropped. Settled 2026-08-15: resolved from the connected mailbox at creation and stored on the row - the mailbox's own display name, or the local part of its address when it has none.

  5. This link has expired 09-expired.html

    Drawn as a revoked share until 2026-08-15, when the screens caught up with the TTL: nobody turns a link off, its seven days run out. Same page, same status code, different cause - and no DELETE route to serve it.
